# 版本锁定协议 V2.2

LOCK解决最终版本唯一性。只有总监可以创建LOCK。

## PERSONA LOCK
路径：批准/PERSONA-001/LOCK-V1.json

触发：
A完成 → B完成 → C PASS → C最终图片GitHub二进制入库 → 总监核对 → LOCK。

必填：
task_id、lock_type=PERSONA、persona_version、C最终资产清单、master_face_repo_path、anchor_repo_paths、image_commit、每张git_blob_sha与sha256、人物固定特征摘要、C PASS交付、created_at、status=LOCKED。

生效后当前进度.active_anchor_lock指向该文件。

## CONTENT LOCK
路径：批准/CONTENT-xxx/LOCK-V1.json

触发：
热点/策划/文案完成 → 图片C PASS → C最终图片GitHub二进制入库 → 独立审核PASS → 总监最终验收。

必填：
task_id、lock_type=CONTENT、最终标题、正文固定提交、C最终资产清单、final_image_repo_paths、image_commit、每张git_blob_sha与sha256、PERSONA LOCK、审核固定提交、总监批准提交、商业关系状态、允许发布范围、禁止旧版本、created_at、status=LOCKED。

## 规则
- 如果图片只存在聊天或只有清单，状态只能WAITING_BINARY_UPLOAD，不能LOCK。
- 发布运营只认当前有效LOCK。
- A图、B图、历史候选标题不能发布。
- LOCK后实质变更必须新建LOCK版本并重审变更范围。
