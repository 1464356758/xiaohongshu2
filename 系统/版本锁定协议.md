# 版本锁定协议 V2.1

LOCK解决“最终到底用哪版”的问题。LOCK只能由总监创建。

## 一、人物LOCK
路径：批准/PERSONA-001/LOCK-V1.json

触发条件：
1. A完成锚点；
2. B审核/修图完成；
3. C终审PASS；
4. 总监核对C最终资产。

必须写入：
- task_id
- lock_type=PERSONA
- persona_version
- C最终资产清单版本
- anchor文件名/资产ID
- 锚点数量
- 人物固定特征摘要
- C PASS交付
- created_at
- status=LOCKED

人物LOCK生效后，当前进度.active_anchor_lock指向该文件。普通带脸CONTENT只能使用当前人物LOCK。

## 二、内容LOCK
路径：批准/CONTENT-xxx/LOCK-V1.json

触发条件：
1. 热点与文案完成；
2. 图片C通过；
3. 内容与合规审核PASS；
4. 总监最终验收通过。

必须写入：
- task_id
- lock_type=CONTENT
- 最终标题
- 正文固定提交
- 图片C最终资产版本/最终ZIP信息（如有）
- 每张最终图文件名/可核验资产ID
- 审核固定提交
- 总监批准提交
- 使用的人物LOCK
- 允许发布范围
- 禁止使用的旧版本
- created_at
- status=LOCKED

## 三、版本规则
- 发布运营只认当前有效LOCK。
- A图、B图、历史候选标题不能发布。
- LOCK后发生实质变更，创建LOCK-V2并重新审核变更范围；旧LOCK不覆盖。
- 任何角色不得自行宣布“锁定”，只有总监写入批准目录后才算LOCK。
