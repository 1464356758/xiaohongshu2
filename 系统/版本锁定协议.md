# 版本锁定协议 V2.2

LOCK解决最终版本唯一性。只有总监可以创建LOCK。

## PERSONA LOCK
路径：批准/PERSONA-001/LOCK-V1.json

触发：
A完成 → B完成 → C PASS → 总监核对C最终资产。

必须包含：
task_id、lock_type=PERSONA、persona_version、C最终资产清单、锚点文件/资产ID、人物固定特征摘要、C PASS交付、created_at、status=LOCKED。

生效后当前进度.active_anchor_lock指向该文件。普通带脸CONTENT只使用当前PERSONA LOCK。

## CONTENT LOCK
路径：批准/CONTENT-xxx/LOCK-V1.json

触发：
热点/策划/文案完成 → 图片C PASS → 独立审核PASS → 总监最终验收。

必须包含：
task_id、content_id（有则填）、lock_type=CONTENT、最终标题、正文固定提交、C最终资产清单、最终图片ZIP信息（如有）、每张最终图文件名/资产ID、PERSONA LOCK、审核固定提交、总监批准提交、商业关系状态、允许发布范围、禁止旧版本、created_at、status=LOCKED。

## 规则
- 发布运营只认当前有效LOCK。
- A图、B图、历史候选标题不能发布。
- LOCK后标题、正文、人物、图片、品牌事实、商业关系等实质变更必须新建LOCK版本并重审变更范围。
- 旧LOCK保留，不覆盖。
- 审核PASS不等于LOCK；只有批准目录存在总监LOCK才算正式锁定。
