# 图片工作流 V2.2

图片是本项目最高优先级。默认4张，允许1至10张，质量优先于数量。

## 两种图片任务
### A. PERSONA_BOOTSTRAP
task_type=persona_anchor_generation。
用途：第一次建立统一人物锚点。
此任务明确免除“已有人物LOCK”要求。

流程：
图片A生成锚点 → 用户上传A实际原图给B → B审核/修图 → 用户上传B最终原图给C → C终审/修图 → 总监创建PERSONA LOCK。

### B. CONTENT
有脸时必须读取active_anchor_lock，并由用户把锁定人物锚点原图上传到图片A当前聊天。
流程：
热点/策划/文案完成 → 图片A → B → C → 独立内容审核 → 总监CONTENT LOCK。

## 摄影底图与文字层分离
1. A优先生成干净摄影底图/妆容细节图。
2. 长中文标题、正文、页码优先使用确定性文字层排版。
3. 文字层逐字使用批准文案。
4. B发现文字问题优先重排文字层。
5. C逐字核对最终中文。

## 图片A
- 直接生成实际图片，不只交提示词。
- PERSONA生成2至4张同一人物锚点。
- CONTENT按page_count生成，默认4张。
- 最终JPG/PNG。
- 路径：产物/图片A/{task_id}/Vn/。

## 图片B
必须看到A实际图。
检查人物一致、五官/手部/发丝、妆容、产品、中文文字、手机可读性和整体完成度。
可修直接修；单页差重做；整组方向错退回A。
路径：产物/图片B/{task_id}/Vn/。

## 图片C
必须看到B最终实际图。
做最终视觉质量检查并直接修可修问题。
PASS后输出最终图片集、最终资产清单，条件允许时输出最终图片ZIP。
路径：产物/图片C/{task_id}/Vn/。

## 图片跨聊天传递
A→B→C之间由用户上传实际原图。不得只复制文字描述。

## 最终资产
C通过后页序、文件名、格式、尺寸和资产版本全部固定。
后续审核、CONTENT LOCK、发布运营只认C最终资产。

## 命名
PERSONA：anchor_front.jpg、anchor_45.jpg、anchor_halfbody.jpg、anchor_detail.jpg（可选）。
CONTENT：01_cover.jpg、02_page.jpg……最多10_page.jpg。
