# 图片工作流 V2.1

图片是本项目最高优先级。默认4张，允许1至10张，质量优先于数量。

## 两种图片任务
### A. PERSONA_BOOTSTRAP
task_type=persona_anchor_generation。
用途：第一次建立统一人物锚点。
重要：此任务明确免除“已有人物LOCK”要求，否则会产生首次启动死锁。

流程：
图片A生成锚点 → 用户上传A实际原图给B → B审核/修图 → 用户上传B最终原图给C → C终审/修图 → 总监创建批准/PERSONA-001/LOCK-V1.json。

### B. CONTENT
用途：正式笔记图片。
有脸时必须读取active_anchor_lock，并由用户把锁定人物锚点原图上传到图片A当前聊天。
流程：
图片A → B → C → 内容与合规审核 → 总监CONTENT LOCK。

## 图片A
- 直接生成实际图片，不只交提示词。
- PERSONA任务生成2至4张同一人物锚点。
- CONTENT默认4张：封面1 + 内页3。
- 最终格式JPG/PNG。
- 交付路径：产物/图片A/{task_id}/Vn/。

## 图片B
必须看到A实际图。
检查人物一致、眼睛/牙齿/耳朵/手部/发丝、妆容、产品、中文文字、手机可读性和整体完成度。
可修直接修；单页差重做该页；整组方向错退回A。
交付路径：产物/图片B/{task_id}/Vn/。

## 图片C
必须看到B最终实际图。
做最终视觉质量检查并直接修可修问题。
PASS后输出最终图片集和最终资产清单。
交付路径：产物/图片C/{task_id}/Vn/。

## 图片跨聊天传递
A→B→C之间由用户上传“实际原图”。不得只复制文字描述。

## 最终资产
C通过后：
- 页序固定；
- 文件名固定；
- 记录格式、尺寸和可核验资产信息；
- 条件允许时生成一个ZIP给用户保存；
- 后续审核/LOCK只认C最终资产。

## 文件命名
PERSONA锚点：anchor_front.jpg、anchor_45.jpg、anchor_halfbody.jpg、anchor_detail.jpg（可选）。
CONTENT：01_cover.jpg、02_page.jpg……最多10_page.jpg。
